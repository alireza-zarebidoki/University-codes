## ساختار پروژه

تمام دستورهای این راهنما باید از **ریشه‌ی پروژه** (پوشه‌ای که مستقیماً حاوی پوشه‌ی `src` است) اجرا شوند، نه از داخل خود `src`. اجرای کامپایل از داخل `src` باعث می‌شود پوشه‌ی خروجی `out` داخل `src` ساخته شود که ساختار پروژه را به‌هم می‌ریزد.

<div dir="ltr">

```
project-root/
├── src/
│   └── com/grandpersia/...
└── out/          ← بعد از کامپایل، این‌جا ساخته می‌شود
```
</div>

## بخش اول: تست خودکار

### معرفی

فایل `SelfTest.java` (در مسیر `src/com/grandpersia/SelfTest.java`) یک کلاس تست خودکار است که مستقیماً با لایه‌ی سرویس‌های پروژه تعامل می‌کند و ۹۳ بررسی مجزا را روی تمام ماژول‌های مشخص‌شده در صورت پروژه اجرا می‌کند. این کلاس از هیچ کتابخانه‌ی خارجی (مانند JUnit) استفاده نمی‌کند و صرفاً بر پایه‌ی یک متد کمکی ساده (`check`) عمل می‌کند که هر بررسی را با برچسب `[PASS]` یا `[FAIL]` گزارش می‌دهد.

### پوشش تست

| بخش | موارد بررسی‌شده |
|---|---|
| فرمول قیمت‌گذاری | محاسبه‌ی قیمت هر ۴ نوع اتاق با ضرایب مربوطه |
| چرخه‌ی رزرو | تمام مراحل از PENDING تا COMPLETED |
| Exception های سفارشی | هر ۷ مورد، با تایید این‌که واقعاً throw می‌شوند |
| جریمه‌ی لغو رزرو | هر ۳ حالت (۱۰۰٪, ۵۰٪, بدون جریمه) |
| الگوی Observer | اطلاع‌رسانی خودکار به لیست انتظار |
| ارتقای عضویت | سناریوی کامل BRONZE تا PLATINUM |
| فرمول فاکتور | تطبیق دقیق با مثال عددی صورت پروژه |
| قفل‌شدن فاکتور | عدم تغییر مبلغ نهایی پس از ارتقای بعدی عضویت |
| پرداخت قسطی | بلاک‌شدن خروج در صورت وجود بدهی معوق |
| خدمات جانبی | هر ۵ نوع خدمت (ماژول ۵) |
| امنیت و احراز هویت | بوت‌استرپ، زنجیره‌ی دسترسی، لاگین/لاگ‌اوت |
| گزارش‌گیری | هر ۶ گزارش (R-01 تا R-06) |
| ذخیره‌سازی فایل | ذخیره/بازیابی کامل، حفظ هم‌ارجاعی اشیاء، تداوم شمارنده‌ی کدها، حالت اولین اجرا |

### اجرا

<div dir="ltr">

```bash
javac -d out $(find src -name "*.java")
java -cp out com.grandpersia.SelfTest
```
</div>

### نمونه خروجی

<div dir="ltr">

```
...
...
==================================================
 TEST SUMMARY: 93 passed, 0 failed (out of 93 checks)
==================================================
 ALL CHECKS PASSED.
```
</div>

### تفسیر نتایج

- اگر همه‌ی موارد `[PASS]` باشند، منطق تجاری پروژه سالم است.
- در صورت مشاهده‌ی `[FAIL]`، متن بالای همان خط دقیقاً مشخص می‌کند کدام بررسی رد شده است. باید بخش کد مرتبط با همان توضیح بازبینی شود.

## بخش دوم: تست دستی

تست خودکار صحت منطق را تضمین می‌کند؛ تست دستی برای تجربه‌ی واقعی جریان کاربری و آمادگی ارائه لازم است.

### اجرای برنامه

<div dir="ltr">

```bash
javac -d out $(find src -name "*.java")
java -cp out com.grandpersia.Main
```
</div>

خروجی اولیه:

<div dir="ltr">

```
SuperAdmin account created (username: admin | password: admin123)
```

</div>

**نکات فرمت ورودی:**

- تاریخ: فرمت `yyyy-MM-dd` (مثال: `2026-08-10`). عدد ماه بر اساس تقویم شمسی تفسیر می‌شود (فروردین=۱ تا اسفند=۱۲) و تعیین‌کننده‌ی فصل (برای محاسبه‌ی قیمت) است.
- جریمه‌ی لغو رزرو بر اساس **تاریخ واقعی سیستم در لحظه‌ی اجرا** محاسبه می‌شود، نه تاریخی که در فیلد ورودی وارد می‌شود.

### نقشه‌ی اتاق‌های پیش‌فرض

| نوع اتاق | محدوده‌ی شماره | قیمت پایه | ظرفیت |
|---|---|---|---|
| STANDARD | 101–120 | 3,000,000 ریال | 2 نفر |
| DELUXE | 201–215 | 4,500,000 ریال | 3 نفر |
| SUITE | 301–310 | 6,000,000 ریال | 4 نفر |
| PENTHOUSE | 501–505 | 10,000,000 ریال | 6 نفر |

### سناریو ۱: زنجیره‌ی ساخت حساب‌ها (کنترل دسترسی)

1. لاگین با `admin` / `admin123`
2. ساخت HotelManager (گزینه‌ی ۱)
3. خروج
4. لاگین با حساب HotelManager
5. ساخت Receptionist (گزینه‌ی ۴)
6. خروج

برای تایید کنترل دسترسی: با یک حساب Receptionist وارد شوید و مشاهده کنید گزینه‌ی «ساخت HotelManager» اصلاً در منو نمایش داده نمی‌شود — هر منو تنها عملیات مجاز برای همان نقش را نشان می‌دهد.

### سناریو ۲: ثبت‌نام مهمان

از صفحه‌ی ورود، گزینه‌ی ثبت‌نام مهمان جدید را انتخاب کرده و یک کد ملی ۱۰ رقمی وارد کنید. سطح عضویت اولیه باید `BRONZE` باشد.

### سناریو ۳: چرخه‌ی کامل رزرو (منطبق بر سناریوی ۱ صورت پروژه)

1. لاگین به‌عنوان Receptionist
2. New Reservation → کد ملی مهمان → شماره اتاق → تاریخ ورود/خروج → تعداد مهمان
3. Check-In با کد رزرو
4. Guest Services → افزودن یک آیتم مینی‌بار
5. Check-Out → مشاهده‌ی فاکتور نهایی

در صورت دریافت پیام بدهی معوق، مبلغی کافی برای تسویه وارد کنید — این رفتار مطابق الزام صورت پروژه است.

### سناریو ۴: رزرو مستقیم توسط مهمان

مهمان می‌تواند بدون واسطه‌ی Receptionist مستقیماً برای خود رزرو ثبت کند (منوی Guest → New Reservation). حداقل پیش‌پرداخت لازم ۲۰٪ مبلغ کل است؛ مقادیر کمتر منجر به `InsufficientPaymentException` می‌شود.

### سناریو ۵: خدمات جانبی

از منوی Receptionist، گزینه‌ی Guest Services:

| خدمت | قاعده‌ی کسب‌وکاری |
|---|---|
| مینی‌بار | آزاد، بدون محدودیت قیمت |
| نظافت فوری | فقط بین ساعت ۸ صبح تا ۸ شب (بر اساس ساعت سیستم) |
| پارکینگ اضافه | برای BRONZE/SILVER هزینه‌بر، برای GOLD/PLATINUM رایگان |
| درخواست تعمیرات | رایگان؛ نیازمند تایید/رد توسط HotelManager |
| سرویس اتاق | آزاد، مشابه مینی‌بار |

### سناریو ۶: قانون جریمه‌ی لغو رزرو

ابتدا تاریخ سیستم را بررسی کنید:

<div dir="ltr">

```bash
date +%Y-%m-%d
```
</div>

سپس بر اساس این تاریخ:

| حالت موردنظر | تاریخ ورود رزرو |
|---|---|
| جریمه‌ی ۱۰۰٪ | تاریخ امروز |
| جریمه‌ی ۵۰٪ | امروز + ۲ روز |
| بدون جریمه | امروز + ۱۰ روز یا بیشتر |

### سناریو ۷: ارتقای خودکار سطح عضویت

رسیدن طبیعی به آستانه‌ی ۵ اقامت (برای SILVER) نیازمند چندین چرخه‌ی کامل رزرو است. دو روش تست:

- اجرای `SelfTest.java` که این سناریو را به‌صورت خودکار تا سطح PLATINUM پوشش می‌دهد
- انجام ۵ چرخه‌ی کامل رزرو → Check-In → Check-Out برای یک مهمان ثابت

### سناریو ۸: گزارش‌گیری

| گزارش | مسیر دسترسی | پیش‌نیاز داده |
|---|---|---|
| R-00001 وضعیت اتاق‌ها | Manager → Reports → 1 | ندارد |
| R-00002 اشغال روزانه | Manager → Reports → 2 | حداقل یک رزرو |
| R-00003 درآمد ماهانه | Manager/Admin → Reports | حداقل یک فاکتور قفل‌شده (پس از Check-Out) |
| R-00004 محبوب‌ترین اتاق‌ها | Manager → Reports → 4 | چند رزرو برای رتبه‌بندی معنادار |
| R-00005 لیست بدهکاران | Admin → Financial Reports → 2 | رزرو Check-In‌شده با فاکتور تسویه‌نشده |
| R-00006 تاریخچه‌ی مهمان | Receptionist/Guest | کد ملی مهمان |

### سناریو ۹: ذخیره‌سازی و بازیابی فایل

1. برنامه را اجرا و چند داده (رزرو، مهمان، خدمت جانبی) ثبت کنید
2. به‌عنوان SuperAdmin وارد شوید و گزینه‌ی «File Storage Status» (گزینه‌ی ۶) را انتخاب کنید — مسیر فایل، وضعیت وجودش، و تعداد رکوردهای فعلی در حافظه نمایش داده می‌شود
3. در همان صفحه، گزینه‌ی ذخیره‌ی دستی را با `y` تایید کنید و مشاهده کنید فایل بلافاصله به‌روزرسانی می‌شود
4. از برنامه خارج شوید (گزینه‌ی ۰ در صفحه‌ی ورود)؛ پیام «Data saved to ...» باید نمایش داده شود
5. برنامه را دوباره اجرا کنید — باید پیام «Previous data loaded ...» را ببینید، نه پیام بوت‌استرپ اولیه
6. بررسی کنید کدهای رزرو جدید از همان‌جایی که متوقف شده بودند ادامه پیدا می‌کنند (بدون تداخل با کدهای قبلی)

> نکته: ذخیره‌سازی از طریق یک Shutdown Hook انجام می‌شود؛ یعنی حتی در صورت خروج ناگهانی برنامه (مثلاً `Ctrl+C`)، آخرین وضعیت سیستم ذخیره خواهد شد.

## عیب‌یابی

پیام‌هایی که با `Error:` شروع می‌شوند، بخشی از منطق تجاری پروژه‌اند و باگ محسوب نمی‌شوند:

| پیام | Exception مرتبط |
|---|---|
| A minimum deposit of ... is required | `InsufficientPaymentException` |
| Room ... is in ... status | `RoomNotAvailableException` |
| Check-out date must be after ... | `InvalidDateRangeException` |

در صورت مشاهده‌ی خطای غیرمنتظره (Stack Trace) یا رفتاری که با این سند مطابقت ندارد، خروجی کامل را برای بررسی نگه دارید.
